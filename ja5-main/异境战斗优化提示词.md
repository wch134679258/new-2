# 樱之异境 · 战斗与地图优化提示词

> 先说结论：问题不是"特效不够多"，是**战斗里根本没有视觉主体**。
> 面板里怪物只有名字 + 一条血条，玩家也没有形象 —— 整场战斗是「点按钮 → 日志出现一行字」。
> 所以这不是"建模粗糙要修模"，是从 0 开始建。下面按这个前提排的阶段。

## P0 · 怪物要有实体（地基，必须先做）

```
任务：给战斗面板加上真正的战斗场景 —— 怪物和玩家都要有可见的 SVG 形象。

现状：battle 面板（Dungeon.vue 344~400 行）里只有 battle.enemy.name、enemyHp 文字、一条血条、
一个日志列表、四个按钮。整个画面没有生物。这是"没有建模"的真正原因。

要做的：
1. 新建 src/components/dungeon/FoeSprite.vue：接受 foe（FOES 里的一项）+ 当前 hp 比例 + 状态，
   输出一只 160×160 的 SVG 怪物。
   关键：必须分部件。每只怪拆成 身体 / 头 / 左臂 / 右臂 / 装饰 5~7 个 <g>，
   各自带 transform-origin 和独立的 class，能被外部用 CSS 单独驱动。
   不分部件的整张图只能淡入淡出，永远像贴纸。
2. 8 只怪各写一个造型（FOES 的 color 字段是主色）：
   - puppet 樱花木傀儡：球关节木偶，肩/肘/膝画成小圆，关节处有木纹裂缝
   - sprite 幼年樱雾精灵：半透明圆身 + 两点眼 + 雾状尾巴（用 opacity 分层叠 3 层）
   - swarm 花瓣蜂群：12~18 片花瓣组成的漩涡，每片有独立旋转相位
   - wraith 湖影幻妖：水波轮廓的人形，下半身逐渐融进水面
   - golem 青苔石魔：3~4 块不规则石头叠成，苔藓用低饱和绿点缀
   - warden 根须守卫：根须缠绕成的躯干，末端有细小分叉
   - elite 樱影护卫：黑色剪影 + 粉色边缘光（stroke 发光）
   - guardian 樱之守护灵：Boss，高度占满 220×220，周围浮一圈花瓣法阵环
3. 新建 BattleScene.vue：把面板中间那块改成「战斗场景」——
   左下玩家（复用小镇里那个小人剪影，或新画一个背对镜头的侧身），
   右上怪物，两者脚下各一个椭圆投影（投影也要分部件，这样能跟着受击动）。
   血条从"面板顶部两条"改成"怪物头顶浮动血条 + 玩家左下角状态条"。
4. 过渡：engage() 时先播 400ms 的"进入战斗"（场景压暗 + 花瓣炸开 + 双方从两侧滑入），
   再显示按钮，别一弹出来就能点。

验收：截图能看到两只具体的生物站在一个有地面的场景里；放大到 200% 时怪物的关节/眼睛
部位是分开的（能看出这是可以动的结构，不是一张图）。
```

## P1 · 打击反馈（最影响手感，做完这条战斗就"活"了）

```
任务：给每一次攻防加视觉反馈。现在点「出手」只有 setTimeout(380) 后日志多一行字。

要做的：
1. 伤害数字：新建 dmgPop 机制 —— 每次扣血在目标身上生成一个飘字（DOM 绝对定位，非 SVG），
   数字上浮 40px + 缩小 + 淡出，时长 700ms；暴击时字号 ×1.6、加 #e0576f 描边、横向抖动 3 帧；
   受击方扣血时数字为白底红字，治疗/加 buff 为青绿。
2. 受击反应（用 P0 拆好的部件做）：
   - 命中：怪物整体 x 轴后退 6px 再弹回（120ms ease-out），同时 filter: brightness(1.9) saturate(.4) 闪一下
   - 暴击：后退 12px + 闪白 + 脚下投影短暂拉长 + 容器震屏（translate ±4px，3 帧，180ms）
   - 闪避：怪物做一次横向位移（错过玩家），玩家头顶冒"未命中"
   - 死亡：怪物分部件逐个散开（每部件随机旋转 ±40°、向外平移 60~120px、opacity→0），
     必须错开 60~90ms，不要全部同时消失
3. 攻击动作：玩家出手时先做一个 120ms 的前冲（translate 30px）+ 斩击弧线
   （SVG path 用 stroke-dasharray 从 0 描到全长，颜色 #fff 加 glow），弧线结束后怪物才掉血。
   整个时序 攻击动画 180ms → 伤害结算 → 受击反应 220ms → 怪物回合，用 requestAnimationFrame 或
   await sleep 串起来，别用嵌套 setTimeout 地狱。
4. 状态提示：buff（必定暴击）时玩家身上加一圈缓慢旋转的虚线环；
   focus 使用后该环消失。现在只有一句文字，玩家看不出自己身上有 buff。

验收：录 5 秒屏幕，光看画面不看日志也能知道「谁打了谁、打中没打中、疼不疼」。
所有动画时长加起来不超过 1.2 秒，不能拖慢战斗节奏。
```

## P2 · 技能系统与特效（"没有技能特效"的正解）

```
任务：把四个按钮升级成技能系统，每个技能配一套专属特效语言。

现状：attack / focus / charm / flee 四个按钮，逻辑都在 Dungeon.vue 653~780 行；
focus 只是把 buff.value 设 true 让下一击必暴击，没有任何画面。

要做的：
1. 新建 src/components/dungeon/skills.js：定义技能表，每项含 { key, name, en, cost, cd, desc,
   fx: 'slash' | 'petalstorm' | 'mirror' | 'pray' }。
   至少 5 个技能，覆盖：单体物理（樱斩）、群体（花雨）、防守反击（镜返）、治疗（祈）、
   控制（缚）。每个技能消耗 mp（现在没有 mp，新增 mp 字段，玩家侧 mp = mystic*4 + 20）。
2. 特效实现，全部不引库：
   - slash 樱斩：两条交叉的白色弧线 path，dashoffset 0→1 在 140ms 内描完，尾迹 60ms 后淡出
   - petalstorm 花雨：从屏幕上方 1/3 区域发射 40~60 个花瓣粒子（复用 usePetals 的 draw 循环，
     不要另开 canvas），带抛物线落到怪物身上，落地时炸成 6 片小瓣
   - mirror 镜返：怪物周围浮现 3 面半透明菱形镜，攻击打到镜上时镜面碎裂（6 条碎片飞散）
   - pray 祈：玩家脚下升起一圈上升的粉色光点 + 一条竖直光柱（linearGradient，opacity .35）
   - bind 缚：从地面长出 4~6 条根须缠住怪物底部，怪物部件整体 y 偏移被锁住
3. 技能栏重做：底部横排 5 个技能格（每个是 44×44 的圆角方块，含图标 + CD 遮罩 + 快捷键数字），
   攻击/闪避/逃跑收进右侧小圆钮。CD 用 conic-gradient 做扇形遮罩，不用图片。
4. 每个技能命中时，怪物身上要叠对应的属性色光（樱斩粉白、花雨深粉、镜返青蓝、缚紫）。
5. 技能命中后弹一行浮动技能名（"樱斩 · SAKURA SLASH"），字号 11px，字距 2px，200ms 内淡出。

验收：五个技能各放一次，不看日志能靠特效颜色/形状分辨出是哪一招。
帧率在 1500×950 窗口下不低于 55fps（特效同时存在时）。
```

## P3 · 副本地图重做成可走（"地图简陋"的正解）

```
任务：把四个区域从"静态背景 + 圆圈按钮"改成可走动的探索地图。

现状：每个区域是一张 1000×580 的 SVG 渐变幕布 + 几棵"三个圆 + 一根杆"的树，
ENCOUNTERS 里的遭遇点是固定坐标的白色圆圈（Dungeon.vue 294~322 行），玩家不能移动，
点圆圈直接弹面板。所谓"地图"其实是 4 张插画 + 12 个热点。

要做的：
1. 换成 2:1 等距地面（和小镇同一套 ip(x,y) 投影，HW=44 HH=22，地图 16×16 格），
   让异境看起来是"小镇的另一面"，而不是另一个游戏的截图。
2. 角色可走：点地面 → 角色沿直线走过去（带缓动 + 走路时轻微上下浮动 3px），
   路上有石头/树根挡路时绕行（简单的 2~3 段折线即可，不用写 A*）。
   复用 BackHill.vue 里那套 me/walking 状态（第 467 行起），别另起一套。
3. 遭遇点实体化：不再是白色圆圈，而是"场景里的生物/物件"——
   樱花木傀儡就站在路边（用 P0 的 FoeSprite，缩到 0.45 倍），你走进 1.5 格范围才触发战斗；
   宝箱是地上的箱子（复用 iso/props.js 的 boxes/chest 画法）；密道是石壁上的门。
   未解锁的加密文符号飘在头顶，不加白圆圈底。
4. 镜头跟随：viewBox 随角色平移（角色始终在画布中心偏下），地图大于视口时才有意义。
5. 分层：远景（雾/山影，opacity .3）→ 地面 → 中景物件 → 角色 → 前景遮挡（树枝、高草，
   opacity .85，画在角色之上），前景必须至少 3 处，这是"有纵深"的关键。
6. 区域交通：四个区域之间加一条"花径"支路 + 传送点（立在边上的樱枝门），
   现在靠顶部四个 tab 直接切，太像后台管理页。

验收：能用鼠标点地面走到任意位置；走近傀儡才开战；截图里能看出近处草挡在角色前面。
```

## 怎么用

1. **P0 和 P1 必须连着做**，中间别停。只有怪物没有打击反馈，观感仍然是死的。
2. P0 做完先看一眼：如果怪物造型就不对（太写实/太卡通/和镇上画风不搭），立刻让它改风格，
   别硬着头皮往下做特效 —— 特效会把这个错放大十倍。
3. 地图这条（P3）改动最大，建议单独开一轮，且做完要回归测试：
   四个区域的遭遇、宝箱、密道、Boss、退出异境全部还要能用。
4. 它要是提出"用 three.js 做 3D 战斗""上个骨骼动画库" —— 拒绝。
   这套画风的优势就是矢量可控、包体小；上 3D 就等于重做美术，跟小镇再也对不上。

## 一句话优先级

没有形象 → 有形象（P0）；有形象 → 有手感（P1）；有手感 → 有招式（P2）；
有招式 → 有地方打（P3）；有地方 → 四个地方不一样（P4）。
中间任何一步没做好，跳过去都会白做。
